# Render baseline — P-LAYOUT-F2 8 (2026-11-01, at `8d3e606`)

Measured with `node scripts/profile-renders.mjs <base url> <label>`. The script drives the installed Chrome with a stand-in React DevTools hook, under Phase 2 (applied from Settings → Profile).

It records two windows of 10 s each, each after the page settles (no page-wide commit for 3 s):
- **Home**.
- **An active call**: Maya Chen (hotkey B), answered and opened.

It ran against two servers:
- **Dev**: `npx vite`.
- **Production**: `npm run build && npm run preview`, the real build. Production React keeps no per-fiber timings, so its cost is the interval callbacks' wall-clock time, with the renders they trigger.

A render is counted the way DevTools counts one: a fiber React flagged `PerformedWork` in the commit, inside a subtree React didn't skip. The dev runs reproduced across three runs: 677 renders a tick on Home and 797 on the call, every run.

## The causes, in order

1. **The 1 s page clock (steady state).**
   - Nearly every commit in the settled windows starts at a `ClockTick`. Home has five (the three seeded nav cards, the queue tiles, `AgentProfile`'s status timer) and the call has six.
   - Each tick re-renders **677 components on Home and 797 on the call**: the whole nav cards, with every lyra `Tooltip`/`Popover` in their rows, and `AgentProfile`.
   - In dev that is up to 97 ms a second, the 10 long tasks per 10 s, which is the choppiness. In production it's under 10 ms a tick, with no long tasks.
2. **The cards' state re-rendering the whole page (an arrival, a toast, a card update).**
   - The page holds the cards (`useNavCards`' overlay, the contact list), and every region reads them through `useWorkspace()`. So any card change re-renders the whole page: about **4,800 components** on Home and about 2,000 on the call.
   - It happens in bursts when something arrives: 5–12 such commits in the seconds after load or after a call arrives, and none in the settled windows.
   - It's the `useWorkspace()` suspect, and it's real, but only around events.

## The suspects checked

- **1 s timers re-render more than the timer text: yes. Cause 1.**
  - lyra's timer props are strings: `ChannelRow`'s `elapsed`, `InteractionNavItem`'s compact `elapsed`, `NeedsOutcomeBadge`'s `elapsed`, `OnHoldBadge`'s `heldLabel` and `AgentProfile`'s `timer`. A tick can only reach them by re-rendering the component that holds them, and with it every tooltip and popover in the card.
  - `ChannelRow` alone also takes an `elapsedOverride` node, which isn't enough while the other strings tick.
- **`useWorkspace()` / settings subscribers re-rendering on unrelated keys.**
  - Settings: no. No settings-store subscriber appears among the origins, and `useSettingsDerived` selects per value.
  - `useWorkspace()`: yes, around events (cause 2). A card change re-renders every reader of the workspace context.
- **`resolveLayout` / `partsIn` recomputed: no.** `useSlotParts` selects a joined string per slot, and no slot hook appears among the origins.
- **Header overflow measurement on every render: no.** It doesn't appear among the origins. The header renders only through `AgentProfile`'s tick.
- **`riseIn` entrance animations replaying on every Home render: no.** Home itself doesn't re-render in the settled windows (only the ticking subtrees do). Around arrivals it does (cause 2), and `riseIn` keys don't change then.
- **Dev-only window handles in production: none cost anything.** `__providers`, `__copilotResults` and `__copilotAnswers` are absent from the built bundle. `__simCustomer` appears only in its dispose-time cleanup comparison, and is never set in production.

## What follows

- **Cause 1** needs lyra.
  - Dave authorized F2-L3: the five timer props also accept a node, so the app passes self-ticking nodes and reads its severities through `useClockValue` selectors that change only at a threshold.
  - P-TIMERS, when timers become controlled, retires those node variants.
- **Cause 2** (a workspace context with selectors, so a card change re-renders only its readers) is a larger change to the controller. It's recorded as a Known gap, not fixed in this batch.
