### Proposed shared pieces for the remaining migrations

All of these live in a new UI-side folder (e.g. `src/contact-handling/`). They consume only provider-context hooks, never the bus or the store directly. Each page imports them and keeps only layout.

- **5b (dial / interaction creation):**
  - `useNavCardUiState()`: page UI state keyed by `journeyId` (`currentThreadId`, `startedFresh`, `liveMessages`, the selected card, the preview thread). It's the re-key P0.5b's prerequisite requires, done once for both pages.
  - `useOutboundDial()`: wraps `dial` and `listOutboundSkills` and returns `startCall`/`quickDial`/`redial`/`dialpadSubmit`, plus `dialpadRequest`/`redialActiveInteraction` state. It's the one voice-dial path both pages use: skills from `listOutboundSkills("voice")`, the agent-leg rule (the leg `invalid-state` → disconnected toast), redial pre-fill and row 16's matching, connecting → connected shown from provider events, and row 19's stale-outcome clearing.
  - `<NewOutboundLauncher>`: the shared `CreateNew` wrapper. Its group scope (row 14) and in-call rule (row 15) are per-page options, a temporary parity exception: Advanced passes Dial Pad only and disabled-during-call, Desk passes its current full picker with dialing allowed. Each page only places it and passes those options.
  - `useContactHistoryActions()`: reopen (row 18), redial, and dismiss-with-history-row (row 19's outcome logging).
  - `useActiveInteractionSwitch(onSave, onRestore)`: switching, with page-supplied panel save/restore callbacks (row 22).
- **5d (voice bar, incoming, wrap-up):**
  - `useLiveVoiceCall()`: the live voice contact from the store, plus `isViewing` and `heldSince` (it replaces `findLiveVoiceThread`).
